## Dashboard pedia a rede inteira em nome de usuário de unidade (~20h BRT)

Depois do guard de leitura entrar, o Arthur (e o `hugobarra`) ainda viam o card de Health Score em `0/0`. O console entregou a causa — **dois** 403 com a mesma natureza:

```
rpc/get_health_score_professor_v3_performance: 403   ← guard criado hoje
rpc/get_conciliacao_experimentais_v2: 403            ← guard de 15/07, pré-existente
"Acesso negado: unidade fora do escopo do usuario"
```

O segundo é anterior a mim e falha igual: **o Dashboard já mandava a unidade errada antes**, o guard novo só somou uma tela ao sintoma.

**Descartado, com verificação:** cadastro do `hugobarra` (id 27, perfil `unidade`, `unidade_id` = Barra, ativo, com vínculo de auth) e RLS em `usuarios` (policy de SELECT é `true` para `authenticated`).

**Causa real** — [`DashboardPage.tsx:171`](../src/components/App/Dashboard/DashboardPage.tsx):

```js
const unidade = filtroAtivo || 'todos';
```

`filtroAtivo` é null em **duas** situações que esse `||` funde numa só: "admin escolheu consolidado" e "o auth ainda não carregou quem é o usuário". Para admin, consolidado é resposta legítima. Para perfil `unidade` é uma afirmação falsa — pede a rede inteira em nome de quem só pode ver a Barra — e os dois guards recusam, corretamente.

O `AppLayout` usa `useUnidadeFiltro`, cujo `filtroAtivo = isAdmin ? unidadeSelecionada : unidadeId`; o `unidadeId` sai de `usuario?.unidade_id`, que é null até o `fetchUsuario` resolver.

**Conserto:** o Dashboard passou a usar `isAdmin ? (filtroAtivo ?? 'todos') : unidadeId` — mesmo padrão já documentado em [`AdministrativoPage.tsx:242`](../src/components/App/Administrativo/AdministrativoPage.tsx) — mais um gate `unidadePronta` que segura o efeito principal, o `useComercialOperacionalResumoV2` e o hook do Health Score enquanto a unidade não é conhecida. Antes, esses três disparavam com `null`.

Corrige de quebra a **Média Alunos/Professor da Barra**, que aparecia 6 por dividir pelos 44 professores da rede em vez dos 19 da unidade.

O **GestaoMensal** recebeu o mesmo tratamento (é a outra tela que consome o Health Score V3): as três abas só montam com `unidadePronta`.

**Detalhe que quase me fez fazer trabalho inútil:** o `isAdmin ? … : unidadeId` sozinho é *no-op*. Como `filtroAtivo = isAdmin ? unidadeSelecionada : unidadeId`, para não-admin ele **já é** o `unidadeId` — reescrever não muda valor nenhum. O que a reescrita entrega é a capacidade de **distinguir os dois nulls**; quem conserta de fato é o gate que vem depois. Por isso o `PreAtendimentoPage.tsx:86` foi deixado como está: repete o padrão, mas não consome nenhuma das RPCs com guard, e a mudança ali seria puro ruído no diff.

⚠️ **O padrão segue espalhado, sem correção:** `ProfessoresPage.tsx:78`, `AlunosPage.tsx:234`, `SalasPage.tsx:91`, `SucessoClientePage.tsx:27` e `TabelaAlunos.tsx:178` usam `unidadeSelecionada || 'todos'`, com a mesma corrida (o `useEffect` de `useUnidadeFiltro` só preenche depois). Se curam sozinhas porque refazem a busca quando a unidade chega — o custo é um 403 transitório no console. `ComercialPage` já faz certo.

**Não verificado:** confirmei que compila e que os tipos fecham, não que a tela do `hugobarra` enche. Falta o teste em produção depois do deploy.

## Health Score V3 negado para todo não-admin (~18h BRT)

O Arthur (gerente da Barra) reportou a aba **Professores → Carteira** exibindo
`HEALTH_SCORE_V3_ACESSO_NEGADO: configuracao exige permissao global`, e a aba **Performance** caindo em tela branca do React Router com `Cannot read properties of null (reading 'numerador')`.

Eram **dois problemas encadeados**, não um.

### 1. O guard de escrita estava numa RPC de leitura

`get_health_score_professor_v3_performance` e `..._snapshot_modal` abriam com `perform fn_health_score_professor_v3_ator_gerenciador()` — função que exige a permissão `professores.editar`. Guard de **gerenciamento** aplicado a endpoint de **leitura**.

**Causa raiz, mais profunda do que parecia:** `fn_usuario_atual_tem_permissao` consulta o sistema granular (`usuario_perfis` + `perfil_permissoes`), e **`usuario_perfis` está vazia — 0 linhas para 29 usuários ativos**. Só passa quem cai no atalho legado dentro de `usuario_tem_permissao`:

```sql
IF (perfil = 'admin' AND ativo) THEN RETURN TRUE;  -- daqui pra baixo consulta tabela vazia
```

Ou seja, **toda checagem de permissão granular do sistema hoje significa "é admin?"**. A permissão `professores.carteira` existe e está ligada aos perfis Gerente/Farmer/Professor — mas ninguém está nesses perfis. O mesmo vale no frontend: `fetchPermissoes` carrega tudo para admin e chama a RPC `usuario_permissoes` (vazia) para o resto, então `hasPermission()` é sempre `false` para não-admin.

**Alcance real:** não era só a Carteira. A mesma RPC alimenta `DashboardPage` e `GestaoMensal/TabProfessoresNew`. Três módulos, 17 contas de perfil `unidade`.

**Conserto:** `fn_health_score_professor_v3_ator_leitura(p_unidade_id)` — admin lê tudo (inclusive consolidado); perfil `unidade` lê só a própria unidade; demais negados. Apoia-se no **escopo por unidade**, que é o modelo que de fato funciona no projeto (mesmo padrão de `get_conciliacao_experimentais_v2`), e não no sistema granular dormente.

O `ator_gerenciador` **não foi tocado** — segue protegendo 14 funções, entre elas as de escrita (`ativar_`, `criar_`, `salvar_`, `simular_`, `fechar_ciclo`).

⚠️ **A troca nas 4 sobrecargas foi feita por `pg_get_functiondef` + `replace` + `execute`**, não reescrevendo os corpos à mão: essas funções foram redefinidas em 28/07 pela migration `20260728225000` e transcrever arriscaria reverter aquele trabalho. A migration aborta sem alterar nada se o guard não for encontrado ou se não trocar exatamente 4.

**Decisão (Hugo):** perfil `professor` (1 usuário, Matheus/Recreio) segue negado. Dar acesso exigiria filtrar pela própria carteira — senão ele veria o score dos colegas de unidade. Não é regressão: ele já não via antes.

### 2. Crash de null na célula de métrica

Bug independente, que atinge **inclusive admin**:

```tsx
{metric?.numerador !== null && metric?.denominador !== null && (
  <p>Base: <strong>{metric.numerador}/{metric.denominador}</strong></p>
)}
```

Com `metric` null, `metric?.numerador` devolve `undefined`, e `undefined !== null` é **true** — a guarda aprova e o `metric.numerador` seguinte derruba a página. E `metric` é null **por desenho**: o fallback de quando não há snapshot define `metric: null` explicitamente. A linha logo acima (amostra) já testava `!== null` **e** `!== undefined`; esta ficou pela metade.

Verificadas as outras 3 ocorrências do padrão no arquivo — todas completam a checagem. O `ModalDetalhesProfessorPerformance` tem `if (!metric) return` antes do uso.

### Pendências

- **Avisar o Luciano**: ele mexeu nessas funções em 28/07 e está ativo hoje. Se redefinir a RPC de performance, o guard volta ao antigo.
- **Ligar o sistema de permissões granulares** é projeto à parte: 29 usuários a mapear entre 6 perfis, mexendo em 4 funções de uma vez. Não fazer às pressas para desbloquear tela.
